# 18 学科离线 RAG 设计

## 目标

为现有数学推理代理新增完全离线、轻量、可复现的本地资料检索能力，覆盖现有 18 个学科。运行时不使用联网检索、外部知识库、向量数据库、嵌入模型或在线 API；模型调用仍只经由平台注入的官方 `client`。

## 合规边界

- `user_agent.py` 继续导出 `ReasoningAgent(client, *args, **kwargs)` 与 `solve(problem, metadata)`。
- 检索层只读取 `problem`，不读取 `metadata["answer"]`、标准答案、隐藏数据或题目顺序。
- 所有资源以 `user_agent.py` 所在目录的相对位置加载；不写死机器绝对路径。
- 资料、清单、代码和测试全部提交到仓库；不在评测运行时下载或构建依赖外部数据的索引。
- 索引仅在进程内从提交的 JSONL 确定性构建，不依赖跨进程缓存。

## 目录

```text
subjects/
  manifest.json
  离散数学/
    cards.jsonl
    examples.jsonl
  数值分析/
    cards.jsonl
    examples.jsonl
  …其余 16 个既有学科目录…
```

`manifest.json` 固定列出 18 个学科、各资料相对路径、条目数和格式版本。每个学科有 20 道代表例题，共 360 道；每题包含题面、答案、关键步骤、方法标签和难度。知识卡包含定理或公式、适用前提、关键词和易错点。

## 轻量检索

- `subject_classifier.py`：使用关键词、数学符号与优先级规则分类；低置信度时返回全局检索模式。
- `local_retriever.py`：使用 Python 标准库构建 Unicode 词段、数学片段和标签的 BM25 倒排索引。
- 每题最多返回 2 张知识卡、3 道例题，并受总字符预算限制。
- `answer_tools.py`：提供确定性的答案完整性、归一化和占位符检查；不执行模型生成代码，不引入 SymPy、LangGraph、MCP 或外部服务。

## 推理集成

`ReasoningAgent.solve` 在既有 policy 生成调用前查询检索器，将结果以“离线参考资料；须自行验证，不得照搬例题答案”的提示段注入。候选生成、答案提取、投票和 finalizer 继续复用现有流程。

若资料文件缺失、损坏或解析失败，检索器返回空上下文，主流程保持可用；`trace` 仅记录分类、命中数量、是否降级等非敏感诊断信息。

## 资源与测试

- 不新增重量级依赖，索引和语料使用 JSONL/标准库。
- 对 manifest、18 学科目录、每类 20 道例题、字段、相对路径和最大资料体积建立测试。
- 对分类、BM25 命中上限、低置信度全局回退和资料缺失降级建立单元测试。
- 对 `ReasoningAgent` 建立集成测试，验证检索不读取 metadata 的答案字段且不改变官方接口。

## 非目标

- 不替换官方 client，不修改 API 凭据或引入任何网络请求。
- 不执行模型生成的 Python 代码。
- 不依赖跨题共享状态或隐藏评测信息。
